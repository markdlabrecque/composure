Phase 1 proves a local, loopback-only Page prototype and its draft/publication model. It is not Composure v1 release acceptance. The evidence below is tied to merged code on `develop` at [`e4b571ae738bf908ebcc24a27d9aae0b77343e0b`](https://github.com/markdlabrecque/composure/commit/e4b571ae738bf908ebcc24a27d9aae0b77343e0b). The merged commits are in this revision's history. The final hosted run tested the reviewed PR source head against its stated base in a synthetic merge checkout; the gate, browser harness, and feature suites are all present at the current merged revision. Earlier squash-merged PR heads themselves are not claimed as ancestors.

## Reproduce the prototype

Use empty site directories. Site A includes the fixed example Page so the second-site demo can prove its content was not copied. The custom configuration gives the required `body` field the label `Story`; export carries that definition, and site B is initialized from it without `--example`.

```sh
CGO_ENABLED=0 go build -o /tmp/composure ./cmd/composure
/tmp/composure init --site /tmp/composure-a --config docs/phase1/examples/page-config-custom.json --example --apply
/tmp/composure config export --site /tmp/composure-a --out /tmp/composure-page.json
/tmp/composure config validate --file /tmp/composure-page.json
/tmp/composure init --site /tmp/composure-b --config /tmp/composure-page.json --apply
/tmp/composure serve --site /tmp/composure-b --addr 127.0.0.1:8081
```

In a separate terminal, keep the exported source site running to check isolation:

```sh
/tmp/composure serve --site /tmp/composure-a --addr 127.0.0.1:8080
```

In Firefox, open `http://127.0.0.1:8081/admin/pages/new`. Fill the `Title` control with `About`, `Path` with `about`, and `Story` with three spaces, then click `Create Page`. The browser's native required-field check accepts whitespace; the server rejects the trimmed empty Story with a `required` error and returns the entered title, path, and Story value. Replace Story with `A` and click `Create Page` again. On the edit page, click `Preview saved draft` and confirm it shows A. Return to edit, click `Publish saved draft`, and run `curl http://127.0.0.1:8081/about`; it returns public A.

Change `Story` to `B` and click `Save changes`. Click `Preview saved draft`; it shows B. While the browser is on that preview, make a separate public request with `curl http://127.0.0.1:8081/about`; it still returns A. Return to edit and click `Publish saved draft`; the same public request now returns B. Stop the B server and restart it with the exact port-8081 `serve` command above. After restart, `curl http://127.0.0.1:8081/about` still returns B. Source site A remains independent: `curl http://127.0.0.1:8080/about` returns 404 and `/example` still returns A's example Page, while `curl http://127.0.0.1:8081/example` returns 404. The retained [`TestPhase1ConfigRoundTrip`](../../tests/integration/config_init_ticket12_test.go) also verifies that a seeded source site's editorial rows are not copied into the configuration-initialized second site. This manual sequence complements the automated browser and process tests; it is not a v1 operational rehearsal.

For the exact pinned browser setup and full local gate, see [`docs/testing.md`](../testing.md). From the repository root:

```sh
bash scripts/install-browser-tests
bash scripts/test-phase1
```

The first command installs Python Playwright 1.58.0, Chromium/headless-shell revision 1208 (145.0.7632.6), and axe-core 4.11.0. The gate runs `bash scripts/test` once, followed by `bash scripts/test-browser` once. It requires the Go application module and fails when required browser prerequisites are missing.

## Accepted implementation decisions

- The [content contract](content-contract.md) defines one Page type with server-assigned UUIDv7 IDs, SQLite draft and immutable snapshot storage, exact path ownership, stored-draft preview, transactional publish, UTC timestamps, startup version/integrity checks, and loopback-only serving. Startup never imports a configuration file. Phase 1's only actor is `local-prototype`.
- The [Page configuration v1 contract](page-config-v1.md) and [validation/export contract](config-validation.md) define a closed Page-only JSON format with stable IDs and supported `short_text`/`long_text` fields. Configuration export is canonical; validation precedes writes; `init --config ... --apply` creates a new site but copies no editorial content. Schema, configuration-format, site-format, and active-configuration revision markers remain distinct.
- The [runtime and deployment ADR](../adr/0001-runtime-content-and-deployment.md) keeps production configuration deploy-only and reserves safe model changes and full recovery for later phases. Phase 1 does not implement deployment or recovery.
- A changed published path returns `path_change_unsupported` pending Phase 5 redirects. Phase 1 also excludes real user accounts, authorization, audit recording, uploads, relationships, menus, Trash, and multi-type content. The historical `admin-flow.md` says first publication only; the merged #10 republish behavior and retained tests are the current evidence and supersede that earlier prose. The admin-flow document is due for its owning documentation update.

The content contract header still says "Proposed for review"; that status label is stale. The contract decisions were reconciled in the [#23 contract-review report](../reports/2026-09-30-ticket-23.md), and executable work follows them in merged feature PRs. Read the contract together with that report rather than treating the stale header as an unresolved product decision.

## Gaps and owners

The prototype implements a foundation for PRD FR-03, FR-05, FR-06, FR-08, FR-15, FR-16, and FR-18; it completes none of these v1 requirements. The content contract maps their later pieces. The PRD still requires five launch types, real editor/admin accounts and direct-request access controls, content and menu history/management, media, redirects, audit, full export/restore, deployment and data-preservation safeguards. Remaining owners are assigned by [`docs/work_plan.md`](../work_plan.md): Phase 2 for authentication, roles, audit and safe upload foundations; Phase 3 for content-model expansion and snapshot restore; Phase 4 for editorial files/media; Phase 5 for menus, Trash and redirects; Phase 6 for deployment and full recovery.

The report provides the evidence base, but the Phase 2 breakdown and remaining-P0 estimate are not complete here: #34 owns those work-plan changes. The PRD's ordered cuts remain unchanged and require Mark's explicit PRD and acceptance-test approval before any P0 is removed. There is no accepted estimate in this report.

No claim is made for production access controls or human security sign-off, full browser coverage across browsers, formal WCAG conformance, the intended-host load baseline, protected-host deployment, full recovery/restore, or v1 release acceptance. The current browser evidence is pinned Chromium at desktop/narrow widths; axe leaves some color-contrast results incomplete. The retained #12 initialization failure injection covers one boundary after temporary database and lock creation but before the schema transaction. The #32 workflow contract tests include parser/AST checks that depend on source layout and should be revisited if that layout changes. Issue #14's historical PR #15 review/auto-merge evidence is a separate process exception: Mark accepted PR #42's prospective reviewed, CI-gated auto-merge demonstration for that bootstrap sequence in [the recorded exception](https://github.com/markdlabrecque/composure/issues/14#issuecomment-5900902711), while the record preserves that PR #15 itself was manually merged without retained stronger-review evidence. This does not relax the independent review and current-base required check for later work.
